# Ender-3 S1 F1 diagnostics candidate

This branch adds UBL probe logging and a host traffic indicator under **Advanced → Info** on ProUI. Port labels are the firmware host serial port numbers. A port is shown for 30 seconds after its last line passed serial framing and was queued. An idle host, an unplugged cable, a wrong baud rate and a host on the wrong COM port can all produce **No recent host traffic**. This is not USB electrical detection or a two-way connectivity test.

For the tested board and release only, generate `Ender3S1-F1-UBL-MPC` with MRiscoC Special Configurations commit `96a61d804810a987a081a0435eaa441e97630a9f` and features `Ender3S1`, `301F1`, `BLT`, `UBL`, `MPC`. Define `S1_F1_20260106_RETAIN_EEPROM` in the generated `Marlin/Configuration.h` and build `STM32F103RC_creality`. This option is off by default. The opt-in accepts the exact predecessor's build hash in addition to the new build's own hash and still requires the expected EEPROM version, record size and payload CRC. It keeps the prior header layout. If validation fails, it does not automatically write defaults to the stored configuration. It does not change how UBL stores or loads slots, nor independently validate every slot.

The predecessor is the official `Ender3S1-F1-UBL-MPC-20260106.bin` (SHA-256 `a21afdbd8e7e871989e94a296fb6c07f09e0fb3253383925c5cb1ca8aedf29c9`). Its settings loader uses a 496-byte record and compares the EEPROM build hash against `0x223F5126`. This allowlist is for that release asset, not arbitrary builds whose settings happen to have the same size. If the update is ever tested, capture current settings and meshes and keep the recovery image before flashing. Compare the first boot with the backup before saving, moving, or heating. An explicit save by this candidate writes its own build hash; rolling back after that save may require restoration rather than automatic retention.
