# Ender-3 S1 F1 diagnostics candidate

This branch adds UBL probe logging and a host traffic indicator under **Advanced → Info** on ProUI. Port labels are the firmware host serial port numbers. A port is shown for 30 seconds after its last line passed serial framing and was queued. An idle host, an unplugged cable, a wrong baud rate and a host on the wrong COM port can all produce **No recent host traffic**. This is not USB electrical detection or a two-way connectivity test.

For this board and release only, generate `Ender3S1-F1-UBL-MPC` with MRiscoC Special Configurations commit `96a61d804810a987a081a0435eaa441e97630a9f` and features `Ender3S1`, `301F1`, `BLT`, `UBL`, `MPC`. Define `S1_F1_20260106_RETAIN_EEPROM` in the generated `Marlin/Configuration.h` and build `STM32F103RC_creality` with its standard flags. This option is off by default. It uses the predecessor's settings build identifier for both reads and writes and still requires the expected EEPROM version, record size and payload CRC. It keeps the prior header layout. If validation fails, it uses defaults in memory, reports the error over serial, and does not automatically write defaults to the stored configuration. It does not change how UBL stores or loads slots, nor independently validate every slot.

The predecessor is the official `Ender3S1-F1-UBL-MPC-20260106.bin` (SHA-256 `a21afdbd8e7e871989e94a296fb6c07f09e0fb3253383925c5cb1ca8aedf29c9`). Its settings loader uses a 496-byte A90 record and compares the EEPROM build hash against `0x223F5126`. This compatibility guard is for that release asset. An intentional save still changes the settings payload. Before a hardware trial, capture current settings and meshes and keep the recovery image. Compare the first boot with the backup before saving, moving, or heating.

The R2 startup messages are `serial ready`, `loading settings` and `settings loaded`. The last message only means the settings routine returned; check the failure message, startup slot, EEPROM readback and actual slot-0 values independently. Startup text can be missed if a host connects after boot.
